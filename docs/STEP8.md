# Step 8 — work, completion and exceptions

Local frontend gate passed on 12 October 2026. All changes remain local; no commit, push, deployment, EAS build or OTA update. Live backend/payment and native-device gates remain open.

Current Figma work, completion, scheduling, cancellation, support and repayment frames are implemented using shared native components. Node and artwork references are in `assets/bookings/README.md`. Editable timing/help fields use the existing Input pattern to satisfy the handoff. Confirmation dialogs allow dismissal without changing the booking.

Provider work start and ready-for-review events are distinct from the customer's explicit completion proof. Provider completion stays Active and cannot release labour. Customer confirmation validates the saved work event and quote version, moves to Completed and separately requests labour release. Completed work can show processing release with zero available labour. Credited labour requires a matching ledger snapshot; no new fee is assessed. Accepted quote scope and payment amounts stay immutable when a separate appointment proposal is accepted.

Inspection/work date proposals retain the confirmed appointment until the customer accepts. Declining preserves the current date. Updated inspection dates also constrain the final quote's work date. Both modes and booking cards reflect accepted dates.

Cancellation requires a reason and explicit confirmation. Refund amount starts unknown/In review; a support decision, processing reference and matching confirmation are separate events. Completed inspections remain non-refundable. Materials recovery uses the actual net funds recorded as received, excluding the already assessed fee. Available materials are recovered immediately; withdrawn/reserved/missing-wallet cases preserve the unpaid or unreconciled remainder. Balance repayment requires a separate sample provider authorization. Hosted repayment has pending/failed/retry/verified states. Deadline-based recovery is an explicit sample event; no client timer or new fee settles a debt. Repayment and customer refund remain independent.

Reports save an owned case with description, timing, requested help and optional fictional evidence. Reporting does not cancel work or resolve money. Case review/outcome and support messages remain scoped to the reporter. Case references are compact; chats retain messages after reload. Sample attachment failure keeps the draft. Real file upload and the shared message attachment journey remain Step 9/backend work.

Only the eligible completed customer can create a review. Editing, discard confirmation and confirmed deletion preserve one review per booking. The complete fictional provider review list updates its aggregate on creation/edit/deletion. Live API review snippets are never re-aggregated in the client. Book again retains the original provider/service and starts a new unpaid request.

Both legacy detail routes now read participant-scoped existing booking history through the known API. They do not map description/notes to a service address, invent a 10% customer fee, claim custody or fund release from a status update, or pretend a cancelled record was saved. New financial/lifecycle writes wait for the real contracts. Account changes remount the network-only owned reader; signed-out access returns to sign-in.
